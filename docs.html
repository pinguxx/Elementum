User Guide & Overview

@wcomp/elementum is an ultra-lightweight, zero-dependency design system of 109 accessible Web Components. It combines fine-grained signal reactivity with standard W3C Web Component APIs, 1:1 Penpot/Figma design tokens, and built-in MCP & AG-UI protocol support.

Zero Runtime Dependencies Elementum has 0 third-party runtime packages. It runs natively in modern browsers, Node.js (SSR), and within React, Vue, Svelte, Angular, Solid, or vanilla HTML without build step locks.
⚡ Micro-Signals

Fine-grained reactive updates directly mutating text nodes and attributes without virtual DOM diffing.

 🎨 1:1 Design Tokens

Bidirectional sync with free open-source Penpot (DTCG standard) and Figma Variables.

 🛡️ WCAG 2.2 AA

Full keyboard navigation, roving tabindex, focus management, and screen reader announcements.

 🤖 AI & MCP Native

Built-in Model Context Protocol server eliminates hallucinations during agent generation.

Developer Architecture

Elementum avoids the bloat of traditional component libraries by replacing heavy virtual DOM runtimes with a ~2KB standard Signal micro-kernel.

Micro-Signals Kernel

Elementum ships a zero-dependency reactive micro-kernel built around signal(), computed(), effect(), and isSignal(). Unlike virtual DOM diffing, signal subscriptions track exact getters lazily at runtime and update only the affected DOM text nodes, attributes, or callbacks when values change via !Object.is(prev, next).

1. Core Reactive Primitives

import { signal, computed, effect, isSignal } from '@wcomp/elementum'; const count = signal(0); const multiplier = signal(2); const product = computed(() => count.value * multiplier.value); console.log(isSignal(count), isSignal(product)); // true, true // effect() runs immediately and re-runs when tracked dependencies change const ac = new AbortController(); const stop = effect(() => { // .peek() reads multiplier without subscribing to future multiplier changes console.log('count:', count.value, 'product:', product.value, 'mult(peek):', multiplier.peek()); }, { signal: ac.signal }); // .subscribe() invokes immediately and on each change; returns an unsubscribe fn const unsub = count.subscribe((val) => console.log('Subscribed count:', val)); count.value = 3; // Triggers product invalidation + active effects (skip duplicates via Object.is) count.value = 3; // No-op (Object.is(3, 3) === true) unsub(); // Stop single subscription stop(); // Or ac.abort() to dispose effects automatically

2. Complete Signals API Reference

API / Member Signature Behavior & Lifecycle Notes
signal(initialValue) Signal<T> Creates a writable reactive container initialized with initialValue.
sig.value T (get / set) Reading inside computed() or effect() subscribes the outer computation. Writing notifies subscribers only when !Object.is(prev, next).
sig.peek() () => T Reads the underlying value without subscribing the currently running effect or computed.
sig.subscribe(cb) (cb: (val: T) => void) => () => void Invokes cb(sig.value) immediately and on subsequent updates; returns a disposal function to unsubscribe.
computed(getter) Computed<T> Creates a lazy, memoized derived signal (subclass of Signal). Marks itself dirty when upstream signals change and recomputes only when .value is read.
effect(fn, options?) (fn, { signal?: AbortSignal, onError?: (err) => void }) => () => void Runs fn() immediately, tracks all signals read during execution (cleaning up stale dependencies on each re-run), isolates exceptions via optional onError, and disposes via returned handle or AbortSignal.
batch(fn) <T>(fn: () => T) => T Coalesces multiple signal writes into a single atomic notification pass while keeping computed() reads fresh inside the batch.
asyncSignal(fetcher, opts?) AsyncSignal<T> First-class async reactive primitive with automatic dependency tracking, AbortSignal race-condition cancellation, stale-while-revalidate .value, .pending, .status, structured .error details, .refetch(), .abort(), .mutate(), and .read().
isPending(source) & NotReadyError (AsyncSignal | () => unknown) => boolean Inspects pending state of an AsyncSignal or derived getter calling .read() without crashing on NotReadyError.
isSignal(value) (val: unknown) => boolean Returns true for Signal, Computed, and AsyncSignal instances (val instanceof Signal).
Coercion & String Helpers valueOf(), toString(), [Symbol.toPrimitive], .length, string methods Supports reactive expression reads like Number(count) and string methods (toUpperCase(), toLowerCase(), trim(), slice(), substring(), includes(), indexOf(), startsWith(), endsWith()).

2b. Async Signals, Batching & Error Details

asyncSignal() tracks synchronous signal reads inside your fetcher, cancels stale in-flight requests via AbortSignal when inputs change, preserves the last resolved .value during refreshes (no visual tearing), and exposes structured error details (message, name, cause, status, timestamp, attempt):

import { signal, batch, asyncSignal, isPending, effect } from '@wcomp/elementum'; const query = signal('web'); const results = asyncSignal( async (abortSignal) => { const q = query.value; // Tracked automatically; stale fetches auto-abort const res = await fetch(`/api/search?q=${encodeURIComponent(q)}`, { signal: abortSignal }); if (!res.ok) throw Object.assign(new Error('Search failed'), { status: res.status }); return res.json(); }, { onError: (details) => console.warn(details.message, details.status, details.attempt) } ); // Atomic multi-write without duplicate fetches batch(() => { query.value = 'signals'; }); effect(() => { if (isPending(results)) console.log('Loading... (showing stale:', results.value, ')'); else if (results.error.value) console.log('Error:', results.error.value.message); else console.log('Resolved:', results.value); }, { onError: (err) => console.error('Isolated effect error:', err) });

3. Three-Way Component Property & Attribute Reactivity

The Elementum base class wires together HTML attributes, JavaScript property assignment, and internal signals so external scripts and frameworks can interact using whichever style they prefer:

import { isSignal } from '@wcomp/elementum'; const btn = document.querySelector('el-button'); const beam = document.querySelector('el-border-beam'); const tabs = document.querySelector('el-tabs'); // 1. Direct property assignment updates the signal & reflects kebab-case HTML attributes btn.variant = 'danger'; // sets btn.variant.value = 'danger' & variant="danger" btn.disabled = true; // sets btn.disabled.value = true & disabled="" beam.colorFrom = '#123456'; // sets colorFrom.value & reflects color-from="#123456" tabs.value = 'metrics'; // updates active tab via observed attribute 'value' // 2. Direct Signal API access remains intact console.log(isSignal(btn.variant)); // true btn.variant.value = 'secondary'; // reflects back to <el-button variant="secondary"> const stopWatch = btn.variant.subscribe((v) => console.log('Variant:', v)); // 3. Attribute mutations sync back into signals automatically btn.setAttribute('size', 'lg'); // updates btn.size.value = 'lg' btn.removeAttribute('disabled'); // updates btn.disabled.value = false Form Controls & Objects On formAssociated controls (such as <el-input>, <el-select>, <el-switch>), live value and checked changes intentionally do not overwrite the host HTML attribute so formReset() always restores the initial HTML default. Non-null object/array signals (such as el-table or el-autocomplete data) stay in JS state without stringifying onto HTML attributes.

4. Authoring Custom Components with Signals & Template Bindings

Inside custom Elementum subclasses, declare observedAttributes alongside signal() fields and wire reactive bindings in render():

import { Elementum, html, css, signal, computed, effect } from '@wcomp/elementum'; export class CounterCard extends Elementum { static observedAttributes = ['count', 'max-width', 'disabled']; count = signal(0); maxWidth = signal('320px'); disabled = signal(false); doubled = computed(() => Number(this.count.value) * 2); #effectsAbort = null; static styles = css`:host { display: block; }`; connected() { // Tie imperative effects to an AbortController cleaned up in disconnected() this.#effectsAbort = new AbortController(); effect(() => { this.emit('count-change', { count: Number(this.count.value) }); }, { signal: this.#effectsAbort.signal }); } disconnected() { this.#effectsAbort?.abort(); } render() { return html` <div style=${() => `max-width: ${this.maxWidth.value}`}> <!-- 1. Direct signal reference in text node --> <span>Count: ${this.count}</span> <!-- 2. Reactive closure for computed / expressions --> <span>Doubled: ${() => this.doubled.value}</span> <!-- 3. .prop binding, 4. ?bool attribute binding, 5. @event binding --> <input type="number" .value=${() => this.count.value} ?disabled=${() => Boolean(this.disabled.value)} /> <button ?disabled=${() => Boolean(this.disabled.value)} @click=${() => { this.count.value = Number(this.count.value) + 1; }} > Increment </button> </div> `; } } customElements.define('counter-card', CounterCard); Template Best Practice Always interpolate either the signal object directly (${this.count}) or a getter function (${() => this.count.value}). Evaluating ${this.count.value} directly outside an arrow function unwraps the value once at initial render and will not stay reactive.

Single-Page Applications (SPA) & Declarative Router

Elementum provides native, zero-dependency SPA routing powered by <el-router>, <el-route>, <el-route-link>, and micro-signals. You can build complete client-side applications with view transitions and browser history support without React Router, Vue Router, or bundlers:

import { ElRouter, ElRoute, ElRouteLink, navigate, currentRoute, signal } from '@wcomp/elementum'; // 1. Declarative Routing in HTML <el-router default="/dashboard"> <el-route path="/dashboard" exact> <h1>Workspace Overview</h1> </el-route> <el-route path="/settings"> <h1>Account Settings</h1> </el-route> <el-route path="/*"> <h1>404 Not Found</h1> </el-route> </el-router> // 2. Navigation Links <el-route-link to="/dashboard" exact>Dashboard</el-route-link> <el-route-link to="/settings">Settings</el-route-link> // 3. Programmatic Navigation & Global Route Signal navigate('/settings'); console.log(currentRoute.value); // '/settings'

Combined with signal() and computed(), state is shared across all routes effortlessly. See the full live implementation in the Pulse Cloud Showcase App.

Declarative Shadow DOM (DSD) Server-Side Rendering

Elementum components support native Declarative Shadow DOM (DSD), allowing server rendering without client hydration flash (FOUC):

import { renderComponentToDSD } from '@wcomp/elementum/ssr'; import { ElButton } from '@wcomp/elementum'; const html = renderComponentToDSD('el-button', ElButton, { variant: 'primary' }, 'Submit Form'); // Output: <el-button variant="primary"><template shadowrootmode="open">...</template>Submit Form</el-button>

Run the zero-dependency Node.js SSR server (npm run ssr → http://localhost:3333/?hydrate=0 for pure Zero-JS DSD vs ?hydrate=1 for progressive hydration), or inspect the pre-rendered Live DSD SSR Demo (source: examples/ssr-server.js).

Form-Associated Custom Elements (FACE)

All input primitives (<el-input>, <el-select>, <el-slider>, <el-checkbox>, <el-radio>) implement the native browser ElementInternals API:

  • Participate automatically in native <form> submission via FormData.
  • Support native validation reporting with setValidity().
  • Handle form reset events cleanly via formResetCallback().

Headless Behaviors, Agent Runtime & Testing Contracts

Every Elementum component supports opt-in unstyled mode, and its underlying interaction, motion, agent, and WAI-ARIA testing primitives are exported as standalone zero-dependency subpaths:

  • @wcomp/elementum/behaviors — 16 composable primitives: createPressBehavior, createRovingFocus, createDismissableLayer, createFocusRecovery, createShortcuts, createDisclosureBehavior, createPopupPositioner, createPresenceBehavior, prefersReducedMotion, createSelectionBehavior, createReorderBehavior, createHistory, highlightMatch, announce, setHostState, and isRTL.
  • @wcomp/elementum/agent — Shadow-DOM-piercing snapshot(root), act(root, cmd, { guard }), and registerWebMCP(root) for AI agents operating live interfaces.
  • @wcomp/elementum/testing — Reusable WAI-ARIA APG (checkAriaPattern), provider-free RTL (checkDirection), and DSD SSR (checkServerRender) contract validators.

MCP Server Setup Guide

Elementum includes a built-in Model Context Protocol (MCP) server (mcp/server.js). It exposes the entire design system's schema, token values, and component constraints directly to AI coding agents like Google Antigravity, Claude Code, Cursor, and Gemini CLI.

Why MCP? AI agents typically hallucinate nonexistent props or default to generic styling. Elementum MCP provides programmatic tool access so agents query live element schemas before writing UI code.

Connecting to Google Antigravity & Claude Code

Add the following configuration to your MCP settings file (e.g., ~/.gemini/antigravity/mcp_config.json or claude_desktop_config.json):

{ "mcpServers": { "elementum": { "command": "npx", "args": ["-y", "@wcomp/elementum"] } } }

Available MCP Tools

list_components

Returns all 109 available Web Components with descriptions and categories.

 get_component_doc

Returns exact attributes, slots, events, and CSS shadow parts for any tag.

 list_tokens

Exposes all design tokens (colors, radii, spacing, elevations) for consistent styling.

 generate_component_markup

Produces accessible, compliant HTML snippets according to design standards.

AG-UI Protocol & Agentic Frontends

Elementum includes a zero-dependency adapter (createAgUiStore, applyJsonPatch, getByPointer) and the <el-tool-call> Web Component to connect AG-UI (Agent–User Interaction Protocol) event streams directly to reactive DOM components.

MCP + AG-UI Architecture Use MCP (mcp/server.js) to give agents design-system schemas at build/prompt time, and use AG-UI (createAgUiStore) to stream live reasoning, text deltas, tool calls, and RFC 6902 state patches into Elementum components at runtime without virtual-DOM re-render cascades.

1. Event-to-Component Mapping

AG-UI Event Type Elementum Store State Bound Component Effect
RUN_STARTED / RUN_FINISHED / RUN_ERROR status, runId, error Toggles loading on <el-prompt-input> and stops streaming cursor on completion.
STEP_STARTED / STEP_FINISHED / THINKING_* thinking, stepName, thinkingText Animates <el-reasoning-card> pulse indicator and updates current step summary.
TEXT_MESSAGE_START / CONTENT / END currentText, messages Appends streaming chunks live into <el-streaming-text> without resetting typing state.
TOOL_CALL_START / ARGS / END / RESULT toolCalls Streams JSON arguments, completion results, and HITL approval state into <el-tool-call>.
STATE_SNAPSHOT / STATE_DELTA state, pathSignal(pointer) Applies RFC 6902 JSON Patches and updates any bound component prop (e.g. <el-number-flow>, <el-chart>).

2. Connecting an AG-UI SSE Stream & State Bindings

import { createAgUiStore } from '@wcomp/elementum'; const store = createAgUiStore({ metrics: { tokens: 0 } }); // Bind AG-UI lifecycle, streaming messages, tool calls, and JSON Pointers directly to DOM elements const dispose = store.bindComponents({ promptInput: document.querySelector('#studio-prompt'), streamingText: document.querySelector('#studio-stream'), reasoningCard: document.querySelector('#studio-reasoning'), toolCallCard: document.querySelector('#studio-tool-call'), stateBindings: { '/metrics/tokens': [document.querySelector('#token-flow'), 'value'], }, }); // Stream events directly from any AG-UI backend endpoint (SSE Response / ReadableStream) const response = await fetch('/api/agent/run', { method: 'POST', body: JSON.stringify({ prompt }) }); await store.connectSSE(response); // Or subscribe to a specific RFC 6901 JSON Pointer signal const tokensSig = store.pathSignal('/metrics/tokens', 0); console.log('Total tokens:', tokensSig.value);

3. Tool Calls & Human-in-the-Loop (HITL) with <el-tool-call>

When an agent starts a frontend or sensitive backend tool with requiresApproval: true, <el-tool-call> renders formatted JSON arguments alongside Approve Execution and Reject controls, emitting bubbling approve and reject events.

<el-tool-call id="deploy-tool" name="deploy_edge_worker" call-id="tc_1" status="awaiting-approval" approval args='{"region":"us-east-1","replicas":3}' ></el-tool-call> <script type="module"> import { createAgUiStore } from '@wcomp/elementum'; const toolEl = document.getElementById('deploy-tool'); const store = createAgUiStore(); toolEl.addEventListener('approve', async (e) => { // Execute client/server action and report TOOL_CALL_RESULT back to AG-UI store store.dispatch({ type: 'TOOL_CALL_RESULT', toolCallId: e.detail.callId, result: { deployed: true, region: 'us-east-1' }, }); }); toolEl.addEventListener('reject', (e) => { console.warn('Operator rejected tool:', e.detail.name); }); </script>

Figma & Penpot Workflow

Design-to-code drift is eliminated with a bidirectional W3C Design Tokens Community Group (DTCG) workflow connecting Penpot (free & open source, design.penpot.app) and Figma directly to src/tokens.css and all 105 Elementum Web Components.

🎨 Penpot Web App

Create or open your design file at design.penpot.app and connect the Penpot MCP Plugin.

Penpot MCP Design System Sync (Code → Penpot)

Elementum includes tools/sync-penpot-mcp.js (npm run penpot:mcp), which connects directly to the Penpot MCP HTTP stream (https://design.penpot.app/mcp/stream?userToken=<YOUR_TOKEN>) to generate the entire Elementum Design System inside your open Penpot file.

Keep Your Penpot MCP Token Private Never commit or paste your personal userToken JWT into source control or public docs. Pass it at runtime via PENPOT_MCP_URL / PENPOT_MCP_TOKEN environment variables or CLI flags.

1. Connect & Run the Synchronizer

  1. Open or create a design file in Penpot.
  2. Open the Penpot MCP Plugin inside the file so your browser session is actively connected, and copy your MCP stream URL or userToken.
  3. Run the synchronizer from your workspace root:
# Pass the full Penpot MCP stream URL npm run penpot:mcp -- --url "https://design.penpot.app/mcp/stream?userToken=<YOUR_TOKEN>" # Or pass only the token (auto-targets design.penpot.app/mcp/stream) npm run penpot:mcp -- --token "<YOUR_TOKEN>" # Or use environment variables (PowerShell / Bash) PENPOT_MCP_URL="https://design.penpot.app/mcp/stream?userToken=<YOUR_TOKEN>" npm run penpot:mcp # Validate generated scripts locally without connecting to Penpot npm run penpot:mcp -- --dry-run

Penpot / Figma → Code Token Compiler

  1. Design in Penpot / Figma: Edit brand colors, radius scales, and elevations in your design file.
  2. Export Tokens: Export W3C DTCG JSON to tokens/penpot-tokens.json.
  3. Run Token Compiler: Run npm run tokens:sync to compile src/tokens.css.

The compiler automatically derives high-contrast Dark Mode tokens, translucent borders (--el-border-translucent), and layered ambient elevation shadows (--el-shadow-card).

How to Contribute

We welcome contributions to Elementum! To maintain world-class reliability, all contributions must uphold our three core engineering pillars:

  • 0 Runtime Dependencies: We do not add third-party runtime dependencies. Everything is written on standard browser platform APIs.
  • 100% Green Test Suite: Every feature must have unit tests in test/.
  • ≥ 95% Line Coverage Bar: Run npm test to ensure project coverage exceeds 95%.
